# Revenue-centric design for ForgeLoop

Adapted from [heliocosta-dev/revenue-centric-design](https://github.com/heliocosta-dev/revenue-centric-design/tree/1942760c2242f609bf63ce2c97204f5a1791bd68),
curated from **Richard ([@richardrx](https://x.com/richardrx))**. Preserve this
attribution, source link and the complete [custom license](LICENSE) in copies
or derivatives. This material is source-available, with a field-of-use restriction;
it is not covered by ForgeLoop's license.

Do not apply this material to betting, casino, gambling or real-money
games-of-chance products, including loot-box and real-money-gaming mechanics.
The upstream permission excludes those uses.

## Apply to the actual journey

Use when product work concerns landing-page clarity, signup, checkout,
onboarding, pricing, useful dashboards or retention. Do not load it for
unrelated storage, security or protocol maintenance. For ForgeLoopAudit,
use it only when changing the auditor's user journey: optimize comprehension,
first successful inspection and actionable evidence, never simulated revenue.

Read [the focused playbook](references/playbook.md) and only the upstream
pinned theme relevant to the request. The playbook links each theme separately.
No updater, media download, external account or Skills CLI is needed.

1. Inspect the implemented journey and real product facts. Identify the user's
   intended outcome, the friction observed and one measurable value event.
   Avoid inventing customer segments, pricing, conversion baselines or proof.
2. Choose a small reversible intervention. State the mechanism as a hypothesis,
   the expected user benefit, the business metric and possible user harm.
   A cited anecdote or statistic is not an expected result for this product.
3. Follow the project's ForgeLoop contract, selected design/accessibility guides
   and canonical `next` actions. This companion neither adds guide IDs or gates
   nor grants lifecycle, evidence, publication or payment authority.
4. Verify the changed journey: understandable copy, complete price and renewal
   disclosure, keyboard/focus behavior, errors, responsive layout and an honest
   empty state. Use the host's available browser tools when behavior changes.
5. Report observed usability separately from measured commercial impact.
   Without sufficient real traffic or a sound experiment, report a design
   hypothesis and qualitative observations, not a conversion improvement.

## Preserve informed choice

Keep cancellation, opt-out and account deletion findable and usable. Explain
consequences accurately and allow the user to continue. Do not introduce fake
urgency, fabricated reviews/logos, concealed charges, misleading plan comparisons,
preselected paid upgrades or obstacles designed to trap users. Defaults should
serve the intended task and remain visible and reversible. Do not add tracking,
paid experiments or third-party services merely to use this companion.

Upstream examples and numeric rules are contextual source claims. Check their
original sources before quoting them as facts; do not treat them as universal
thresholds, verified research or financial guidance.

## Suggested review result

Return the inspected journey, observed friction, selected source principle,
proposed change, user-value metric, guardrail metric, verification performed
and unresolved measurement. Implementation remains within the user's scope.
The companion's review is advisory and cannot establish `COMPLETE` or `VALID`.
